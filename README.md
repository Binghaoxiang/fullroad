# Severo —— STM32F429IGT6 舵机串口精准控制（50 寸主控板）

在 **50 寸主控板（STM32F429IGT6）** 上用 Keil MDK 实现对舵机（国华 GH 系列标准 3 线舵机）的
**串口角度精准控制**，并支持**分档位点动**（多级指令转动）。

- 串口输入角度，舵机转到该角度，指令分辨率 **0.001°**、脉宽分辨率 **0.5 µs（0.045°）**
- 硬件 PWM 输出，**50.000 Hz / 20.000 ms**，软件不参与波形翻转，**抖动为 0**
- 角度用整数毫度运算，无浮点、无累计误差
- 带**斜率限制**（默认 180°/s），不会像普通例程那样"甩"到目标位置
- 带**端点标定**与**零点修正**，可以补偿舵机个体差异和机械安装偏差
- **N1~N4 分档 + `+`/`-` 点动**：0.1° / 1° / 5° / 45° 四档，对光时手调不用敲角度

## 0. 新硬件勘察结论（从原理图/PCB 逆推）

工程资料：`HardWare\Serveo\ProPrj_50寸主控026-09-21.epro`（嘉立创 EDA，含 2 块板）
与 `ADC64 for mcu g.PcbDoc`（Altium）。有用信息如下：

| 项目 | 实际情况 |
|---|---|
| 主控 MCU | **STM32F429IGT6**（LQFP176，1 MB Flash，192 KB SRAM + 64 KB CCM） |
| 晶振 | X2 = X32258MOB4SI = **8 MHz**（C29/C30 = 12 pF 负载电容） |
| 命令串口 | **UART8（PE1=TX / PE0=RX）← CH340C ← Type-C**，插 Type-C 即虚拟串口 |
| 其它串口 | UART2（PA2/PA3）、UART4（PA0/PA1），原理图上给 WiFi/模块 |
| SPI | SPI1/SPI4/SPI5 挂 16 路 FPC 采集口；H1/H2/H8/H9/H10/H11 是 6 个 2.54 三针 SPI 口 |
| 采集 | 16 路 FPC（XF3M 1.0mm-15P）+ 20 脚 H5，模拟通道网络 01~20 |
| 其它 | WiFi（WIFI_IO/WIFI_RESET/STA）、LED1(PC4)/LED2(PC5)、SWD、原生 USB（PA11/PA12） |
| 舵机接口 | **板上没有**。未使用的空闲脚：PD12(100 脚)、PB6(164 脚)、PA8(119 脚)、PF9(27 脚) |

结论：这块板本质是**多路 SPI 采集主控**，舵机信号需要从空闲脚**飞一根线**出去。
本工程默认用 **PD12（LQFP176 第 100 脚）= TIM4_CH1**，其余三个空闲脚都留了宏，改一行即可换。

> 完整的逐引脚网络表（从原理图逆推，176 脚全部列出）见
> [`docs/50寸主控网络表.txt`](docs/50寸主控网络表.txt)，改硬件前先查这个文件。

## 2. 硬件连接

| STM32F429IGT6（50 寸主控板） | 外部 | 说明 |
|---|---|---|
| **Type-C 口**（CH340C） | 电脑 USB | 免 USB-TTL，直接出现虚拟串口 |
| **PD12**（TIM4_CH1，第 100 脚） | 舵机 **信号线**（黄/橙/白） | 板上无舵机座，需飞线 |
| 板上 **GND** | 舵机 **地线**（棕/黑） | **必须共地**，否则脉宽会漂 |
| 外部 5~6 V 电源 + | 舵机 **电源线**（红） | 见下方供电说明 |

> 飞线建议：从 PD12（100 脚）背面过孔或最近的无连接焊盘引一根 30AWG 线，
> 终点焊一个自己加的 3 针 2.54 排针（信号/5V/GND），以后插拔方便。
> 也可以把舵机线直接压进 FPC 空脚，但**不建议**（FPC 是 1.0 mm 间距，容易短路）。

### ⚠ 这些"引出来的脚"不能接舵机信号

| 位置 | 实际是什么 | 能不能接 |
|---|---|---|
| **H5（20 脚排针，丝印 01~20）** | **模拟通道**。例如 net `18` = H5.18 ↔ FPC7.7 ↔ FPC12.7，直连两块采集板的运放输入，**不通 MCU** | ❌ 绝不接：舵机不会动，还会把 50 Hz 方波灌进模拟输入 |
| H1/H2/H8/H9/H10/H11 的 **1、2 脚** | SPI_SCK / SPI_MISO | ❌ 接 5 V 会烧 SPI |
| H1/H2/H8/H9/H10/H11 的 **3 脚** | 原理图上悬空（只有一小截未连接的导线） | ✅ 可以只接**信号线**（配合 PD12 飞线） |
| H6（8 脚全 +3P3V）/ H7（8 脚全 GND） | 电源测试排针 | GND 可借用；+3P3V 不能给舵机供电 |
| CN1（4 脚） | SWD 调试口 | ❌ 占用后无法下载 |

结论：**舵机信号只能从 PD12 飞线**，板上没有任何"已引出且空闲的 MCU 引脚"。

**线色怎么认**：标准舵机 3P 插头里 **中间那根针永远是 VCC(+5V)**，一般是红色；
一侧是信号线（黄/橙/白），另一侧是地线（棕/黑）。GH/国华、MG995、SG90 都遵循这个规范。
所以：**红 = 电源正极**，棕/黑 = 地，黄 = 信号（接 PD12）。
若线被换过色，别猜——拆后盖看 PCB 丝印：`+`/`VCC` 接红，`S`/`PWM` 接黄。

> ⚠ 这类舵机基本没有反接保护，电源接反或把 5 V 灌到信号线上会立刻烧掉内部 H 桥。

### ⚠ 供电：这是"舵机不精准"的第一大原因

- **不要**从主控板的 3.3 V/5 V 取电给舵机。舵机堵转电流可达 1~3 A，会把 MCU 电源拉塌，
  表现为角度乱跳、串口复位、舵机嗡嗡响，严重时重启。
- 请用独立 5~6 V / ≥2 A 电源，舵机端子处并 **470~1000 µF 电解电容**，
  电源地与主控板地**单点连接**。
- STM32 输出 3.3 V 逻辑，绝大多数舵机把 >2 V 判为高电平，一般可直连；
  若遇到个别舵机不识别，加一级 74HCT245 / 74LVC1T45 电平转换即可。

### 换引脚 / 换定时器

只改 `Core/Inc/config.h` 第 3 节那几个宏即可。已确认空闲的定时器输出脚：

| 引脚 | 定时器通道 | LQFP176 脚号 | config.h 里怎么写 |
|---|---|---|---|
| PD12 | TIM4_CH1 | 100 | 默认，无需改 |
| PB6 | TIM4_CH1 | 164 | `SERVO_GPIO=GPIOB`、`SERVO_PIN=6`、`AHB1EN=RCC_AHB1ENR_GPIOBEN` |
| PA8 | TIM1_CH1 | 119 | `SERVO_TIM=TIM1`、`SERVO_TIM_APB2EN=RCC_APB2ENR_TIM1EN`、`AF=1` |
| PF9 | TIM14_CH1 | 27 | `SERVO_TIM=TIM14`、`AF=9`、`GPIOF` |

时钟链、PSC、GPIO 复用全部由代码按实际总线自动计算，不需要你再算分频。
（当前实现使用 **CH1**，若换到 CH2~CH4 需同步改 `board.c` 里 `CCMR1/CCER/CCR1` 三处，注释已标出。）

## 3. 编译与下载

1. 双击 `MDK-ARM/Severo.uvprojx` 打开工程。
2. 确认器件：`Options for Target → Device` 应为 **STM32F429IGTx**（工程已设好，若你的 DFP 版本不同会提示，重选一次即可）。
3. `F7` 编译 → 应显示 `0 Error(s), 0 Warning(s)`，代码约 **7.8 KB**。
4. `Options → Debug` 选下载器（ST-Link / J-Link / DAP），`Flash` 页勾选 `Reset and Run`。
5. 插上板子的 Type-C，串口助手打开新出现的 COM 口，**115200 / 8 / N / 1**，发 `Q` 应看到状态行。

### 回到旧 F407ZGT6 板

改三处即可：`config.h` 里器件改 `STM32F407xx`、Keil 工程 `Device` 选 `STM32F407ZGTx`、
启动文件换成 `startup_stm32f407xx.s`（工程里两套文件都留着），主频会按 `BOARD_SYSCLK_HZ` 自动适配。

### 晶振不是 8 MHz 的板子

默认按 **8 MHz** 无源晶振配置。若是 25 MHz 晶振板，改**两处**并保持一致：

| 位置 | 改成 |
|---|---|
| `Core/Inc/config.h` → `#define BOARD_HSE_HZ` | `25000000UL` |
| Keil → `Options → C/C++ → Define` 里的 `HSE_VALUE=8000000` | `HSE_VALUE=25000000` |

代码本身是健壮的：**HSE 起振失败或 PLL 不锁定时会自动退回 HSI 方案**，
UART 波特率与 PWM 频率都按实际主频重算，系统仍能正常工作（上电横幅会显示 `SRC=HSI`）。

## 4. 串口协议

- 一条命令以 **CR 或 LF** 结尾（串口助手勾选"发送新行"即可），大小写不敏感，前导空格忽略。
- 角度单位是**度**，可带 3 位小数、可为负；未特殊说明时角度都受 `L` 命令设定的软件行程约束。

### 4.1 串口助手设置（XCOM / sscom / 友善串口助手都通用）

| 项目 | 设置 |
|---|---|
| 端口 | 插上板子 Type-C 后新出现的 COM 号（设备管理器 → 端口 里看） |
| 波特率 / 数据位 / 停止位 / 校验位 | **115200 / 8 / 1 / 无** |
| 流控 | 无（None） |
| 接收显示 | **文本 / ASCII**，不要勾"十六进制显示" |
| **发送新行 / 加回车换行** | **必须勾选** ← 不勾就收不到结束符，命令完全不执行 |
| 定时发送 / 循环发送 | 关闭 |

打开串口后按一下板上复位键，应看到开机横幅：

```
=====================================================
  STM32F429IGT6  UART SERVO CONTROLLER  v2.0
-----------------------------------------------------
  SYSCLK=180MHz  SRC=HSE+PLL
  PWM : PD12/TIM4_CH1  50Hz  0.5us/step
  UART: PE1/PE0 (UART8->CH340C Type-C)  115200 8N1
  START=90.000deg  LIM=0.000..180.000deg
  H = help   Q = status
=====================================================
```

在发送框输入 `A90` 并回车 → 回复 `A=90.000 P=1500`，舵机就转到 90°。
对光调试时更常用点动：`N2` 选 1° 档，然后点 `+` / `-`（或 `+5` 一次走 5 步）。
小技巧：把 `+`、`-`、`N1`、`N2`、`N3`、`C`、`Q`、`X0`、`X1` 用助手的"多条发送/快捷指令"存成按钮。

| 命令 | 含义 | 示例 | 回复 |
|---|---|---|---|
| `A<deg>` | 转到指定角度（带斜率限制） | `A90.5` | `A=90.500 P=1505` |
| **`+[n]`** | **按当前档位正转 n 步（n 默认 1）** | `+5` | `A=95.000 LVL=2 STEP=1.000 P=1055` |
| **`-[n]`** | **按当前档位反转 n 步** | `-` | `A=94.000 LVL=2 STEP=1.000 P=1044` |
| **`N[1..4]`** | **选择点动档位：0.1° / 1° / 5° / 45°，`N` 单独发=查询** | `N1` | `A=94.000 LVL=1 STEP=0.100 P=1044` |
| `P<us>` | 直接给脉宽（0.5 µs 精度，**不走斜率**，用于示波器/标定） | `P1500` | `A=90.000 P=1500` |
| `C` | 回到行程中点 | `C` | `A=90.000 P=1500` |
| `L<min>,<max>` | 设定软件行程（角度限位） | `L0,180` | `LIM=0.000,180.000` |
| `W<min>,<max>` | 设定脉宽标定端点（角度↔脉宽映射） | `W600,2400` | `W=600,2400` |
| `T<deg>` | 零点修正（补机械安装偏差，只影响输出脉宽） | `T-1.5` | `TRIM=-1.500 P=1485` |
| `S<deg/s>` | 最大角速度，`0` = 不限速 | `S90` | `VMAX=90.0` |
| `X<0\|1>` | 关/开脉冲输出（关掉=舵机卸力、不发热） | `X0` | `EN=0` |
| `Q` 或 `?` | 查询全部状态 | `Q` | 见下 |
| `R` | 恢复 `config.h` 里的默认参数 | `R` | `OK RESET` + 状态 |
| `Z` | 往返扫掠自检（约 3 s，期间命令排队，结束后执行） | `Z` | `SWEEP START` … `OK SWEEP` |
| `V` | 版本 / 主频 / 波特率 | `V` | 两行信息 |
| `H` | 帮助 | `H` | 命令表 |

`Q` 的输出字段：

```
A=90.000 P=1500 TGT=90.000 MOV=0 EN=1 VMAX=180.0 LIM=0.000,180.000 W=500,2500 TRIM=0.000 LVL=2 STEP=1.000 SRC=PLL UP=12s
```

- `A` 当前角度、`P` 当前实际脉宽、`TGT` 目标角度、`MOV` 是否还在运动
- `EN` 脉冲使能、`VMAX` 速度上限、`LIM` 软件行程、`W` 标定端点、`TRIM` 零点
- `LVL`/`STEP` 当前点动档位与步长、`SRC` 主频来源（`PLL`=外部晶振、`HSI`=内部 RC 兜底）、`UP` 运行秒数

### 示例会话

```
> V
SEVERO SERVO CONTROLLER v2.0
...
> A45
A=45.000 P=1000
> Q
A=45.000 P=1000 TGT=45.000 MOV=0 EN=1 VMAX=180.0 ...
> N2             ← 选第 2 档（1°）
A=45.000 LVL=2 STEP=1.000 P=1000
> +5             ← 正转 5 步 = 5°
A=50.000 LVL=2 STEP=1.000 P=1055
> N1             ← 第 1 档 0.1°，精调
A=50.000 LVL=1 STEP=0.100 P=1055
> -3
A=49.700 LVL=1 STEP=0.100 P=1052
> S30            ← 限速 30°/s
VMAX=30.0
> A135           ← 90° 行程需要 3 s 走完
A=135.000 P=2000
> X0             ← 关脉冲，舵机松手
EN=0
```

点动（`+`/`-`）是**相对当前目标角度**累加，不是相对实际位置，所以连续快速点动不会丢步；
已经到行程端点时会回 `AT LIMIT`。

错误回复统一为 `ERR <原因>`：`ERR SYNTAX`、`ERR CMD`、`ERR RANGE 0.000..180.000`、
`ERR LINE_TOO_LONG`。角度**超出行程会被拒绝而不是静默夹住**，方便上位机发现参数错误。

## 5. 精度到底能到什么程度

这不是"调几个参数看起来差不多"，而是可以逐项验证的：

| 指标 | 本项目 | 说明 |
|---|---|---|
| PWM 周期 | 20.000 ms（50.000 Hz） | TIM4 计数时钟 2 MHz（180MHz÷45），ARR=39999 |
| 脉宽分辨率 | **0.5 µs** | 对应 180° 舵机 **0.045°/LSB** |
| 脉宽抖动 | 0 | 纯硬件 PWM，软件只在数值变化时写 CCR |
| 指令分辨率 | 0.001° | 内部整数毫度，无浮点误差 |
| 点动档位 | 0.1 / 1 / 5 / 45° | 最低档≈2 个 LSB，实际可用下限 |
| 映射误差 | < 0.5 µs | Q24 定点增益 + 四舍五入（脚本穷举 0~180°，最大 0.44 µs） |
| 斜率精度 | 1 ms | 1 kHz 时基 + 余数累加，低速也不丢步 |
| 斜率超调 | 0 | 接近目标时钳位，绝不越过 |
| 波特率误差 | −0.10% | 45 MHz / 115200（UART8 在 APB1），远小于 2% 容限 |

**但最终的机械精度由舵机本身决定**，这几点必须知道：

1. 舵机内部是电位器 + 死区比较，普通模拟舵机死区约 **3~8 µs**（≈0.3~0.7°），
   数字舵机约 1~2 µs。所以指令给 90.000°，实际停在 90.0°±0.5° 属于正常。
2. 舵机个体差异：同一型号不同个体，"0°/180°"对应的脉宽可能相差 50~150 µs。
   **必须按下节标定**，否则算得再准也没用。
3. 供电电压波动、齿轮间隙（回程差）、负载力矩都会直接影响重复定位精度。
   回程差只能单向逼近（每次都从同一方向靠近目标）来规避。

用示波器验证：接 PD12，发 `P1500`，应看到 **高电平 1500 µs、周期 20.000 ms**；
发 `P500` / `P2500` 看端点是否精确。

## 6. 标定流程（3 步，约 5 分钟）

> 目标：让"发 0° / 90° / 180°"时，舵机臂真的停在机械 0° / 90° / 180°。

**第 1 步：找真实端点（改 `W`）**

舵机先空载。用小步长逼近，边看边记：

```
A0        → 记下实际停在哪（比如还差 3°才到机械零点）
P480      → 继续往小走，直到刚好到机械零点且不顶死（听到堵转声就往回退 10 µs）
P2530     → 往另一端走，找到机械 180° 位置
W480,2530
```

`P` 命令绕过软件行程，专门用来探边界；探到后立刻 `W<min>,<max>` 固化映射。
注意：**不要长时间停在顶死位置**，会堵转发热。

**第 2 步：补安装偏差（改 `T`）**

舵机臂装到轴上时通常错开几个齿。发 `A90`，如果实际停在 87°，
说明输出偏小，用 `T+3` 补回来（`T` 加在角度上，只改脉宽不改变目标值）：

```
A90
T3        → 实际到位角 +3°，再微调到完全对中
T2.7
```

**第 3 步：验证**

```
W480,2530
Z         → 自动往返扫掠，观察两端是否都到位、有没有顶死
A0 / A90 / A180
```

参数目前放在 RAM 里，**掉电不保存**。标定完成后，把最终值写回 `config.h`
第 4 节的 `SERVO_PULSE_MIN_US_DEF / SERVO_PULSE_MAX_US_DEF / SERVO_TRIM_MDEG_DEF`，
重新编译即可永久生效（若想在线保存，见第 8 节扩展）。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 串口无任何输出 | ①Type-C 只插了充电线（要数据线）②没装 CH340 驱动 ③波特率不是 115200 ④晶振不是 8 MHz 且未改 `HSE_VALUE` ⑤串口被别的软件占用 |
| 输出乱码 | 波特率/晶振配置不一致；先发 `V` 看 `SYSCLK` 是否 180 MHz |
| 点 `+`/`-` 不动 | ①在最低档（0.1°）时约等于 2 个 LSB，可能一次只走半个 LSB → 连按两次 ②已在行程端点（会回 `AT LIMIT`） |
| 舵机不动 | ①信号线没接到 PD12 ②`EN=0`（发 `X1`）③舵机电源没接/电压不足 ④`P` 值超出舵机识别范围 |
| 舵机一直抖 / 嗡嗡响 | ①电源功率不足（最常见）②目标正好在死区边界，微调 `T` 0.2° 让它离开边界 ③共地不良 |
| 角度到了但顶死、发热 | 端点标定过头，把 `W` 或 `L` 往回收 20~50 µs / 2° |
| 每次上电位置不一样 | 电位器式舵机的正常现象（±0.5°）；要更高重复精度需要改闭环（见扩展） |
| 运动一顿一顿 | 速度上限设太小（`VMAX` 很小），0.5 µs 量化在低速下会显得明显；适当加大 `S` |
| Keil 提示器件包版本不符 | `Options → Device` 重新选一次 `STM32F429IGTx`，不影响代码 |
| 中文注释在 Keil 里乱码 | `Edit → Configuration → Editor → Encoding` 选 **UTF-8** |

### SWD / J-Link 连不上怎么查（按顺序）

1. **DLL 版本**：Keil 自带 `C:\Keil_v5\ARM\Segger\JLinkARM.dll` 是 **V5.10h（2016）**，
   而 J-Link 固件是 V9.60（2021），老 DLL 沟通不了新固件。用
   `C:\Program Files\SEGGER\JLink_V986\JLinkDLLUpdater.exe` 勾 Keil MDK 一键替换，
   或手工把新版 `JLinkARM.dll` 复制过去（本项目已替换并把旧版备份成 `JLinkARM.dll.bak510h`）。
2. **别让 ini 覆盖器件**：`MDK-ARM\JLinkSettings.ini` 里的 `[FLASH] Device` 必须是
   `STM32F429IGTx`、`Override = 0`。若写成 `Device="ARM7"` + `Override = 1`，
   J-Link 就用 ARM7 的时序去连 F429，日志里会看到 `Device "ARM7" selected`。
3. **降速**：`Options → Debug → J-LINK → Settings → Port: SW，Max Clock = 1 MHz`
   （杜邦线/长线跑 4 MHz 会 `Failed to initialize DAP`）。
4. **接线顺序**：板上 CN1 是 `1=+3P3V  2=SWDIO  3=SWCLK  4=GND`，
   而 J-Link 20 针是 `1=VTref 2=SWDIO 3=GND 4=SWCLK`。
   **不能按 1-2-3-4 直连**，否则 SWCLK 落到 GND 上。
5. **用命令行判定是"驱动问题"还是"硬件问题"**（不进 Keil，最快）：

   ```
   & 'C:\Program Files\SEGGER\JLink_V986\JLink.exe' -NoGui 1 -CommanderScript test.jlink
   ```
   `test.jlink` 内容：`si SWD` / `speed 1000` / `device STM32F429IGTx` / `connect` / `q`

   | 现象 | 结论 |
   |---|---|
   | `VTref=3.3V` + `DAP initialized successfully` + `Can not attach to CPU` | SWD 通了但内核不响应 → 查 NRST 是否被拉低、VCAP1/VCAP2 电容是否焊了（应为 2.2 µF）、内核供电 |
   | `Failed to initialize DAP` | 物理层问题：GND 没接好 / 线太长 / SWCLK 与 GND 接错 |
   | `VTref=0V` | 板子没供电，或没接 VTref |

6. **「DAP 稳定应答、CPU 永远挂不上」是内核域故障**（本板实测结论）：
   三种复位策略（normal / core / reset-pin）全部失败，说明不是固件或低功耗状态造成的。
   F429 的 SWD 调试口在 3.3 V 域、内核总线在 1.2 V 域，**DP 活着而 CPU 挂不上，就是 1.2 V 内核域没起来**：
   - 量 **VCAP_1（81 脚）/ VCAP_2（125 脚）对地电压，应为 1.2 V**（不是 0 V、不是 3.3 V）；
   - 两颗 **2.2 µF X7R** 必须贴（漏贴、贴成 100 nF、或短路到 VDD 都会这样）；
   - 再查所有 VDD 脚（15/23/36/49/62/72/82/91/103/114/127/136/149/159/172）是否 3.3 V、有无虚焊；
   - 以上都正常仍不行，则考虑芯片损坏或非原装。

   一键重试 26 次的探针脚本见 [`tools/swd_probe.ps1`](tools/swd_probe.ps1)
   （`powershell -ExecutionPolicy Bypass -File .\tools\swd_probe.ps1 -Seconds 30`，
   跑的时候连按复位键，看有没有「连接成功」或「DAP 通」）。

## 8. 扩展方向

- **多路舵机 / 双轴**：`servo.c` 的状态是单例，改造成 `servo_t[MAX_CH]` + 数组化 API 即可；
  TIM4 的 CH1~CH4（PD12~PD15）可用同一个 50 Hz 时基，四路完全同步，
  做 X/Y 双轴对光时这就是最省事的结构。
- **和 ADC64 采集联动**：主控板有 SPI1/SPI4/SPI5（`SPI4_CS0~CS4`、`SPI5_CS0~CS4` 等片选），
  可把"转一个角度 → 读一次 64 路光强 → 找最大值"做成闭环寻峰，这才是对光自动化的关键。
- **参数掉电保存**：STM32F429 的 Flash 末扇区（1 MB 器件为 `0x080E0000`）够用，
  在 `cmd.c` 里加 `SAVE` 命令，擦写该扇区即可。
- **闭环**：换成带位置反馈的舵机（4 线）或加编码器，
  用 TIM 输入捕获读编码器，PID 输出直接改 `servo_set_angle()`。
- **轨迹/联动**：`servo_set_angle()` 是"设目标 + 后台规划"的模型，
  外部只要按时间轴喂目标角度就能做插补；`servo_jog()` 则适合手动机动。

## 9. 关键实现说明（给要改代码的人）

- **`board_clock_init()`**：完整重配时钟树。先切 HSI 再关 PLL，避免改 PLLCFGR 时 CPU 失去时钟；
  Flash 5WS + 预取/I-D Cache；AHB 180 / APB1 45 / APB2 90；
  PLL 的 M 由实际时钟源算出，所以 HSE 失败退回 HSI 时仍是 180 MHz。
- **`board_servo_pwm_init()`**：PSC 由 `board_timer_clk_hz()` 动态算出，
  配合 `SERVO_PWM_TICKS_PER_US`，保证无论主频怎么变，计数时钟都是 2 MHz、周期都是 **20.000 ms**。
  CCR 使能预装载（OC1PE），写 CCR 不会切出畸形波形。
- **`servo_tick_1ms()`**：1 kHz 里只做整数加法/乘法和移位，没有除法、没有库函数，
  反汇编约 60 条指令，中断开销 1 µs 量级（180 MHz）。低速时靠 `s_slew_acc` 余数累加，
  0.1°/s 这种极慢速度也不会"卡住不动"。
- **`servo_jog()`**：在临界区里对 `s_tgt_mdeg` 累加 `档位步长 × 步数` 再限幅，
  以"目标"为基准而不是"实际位置"，连续快点不丢步。
- **`map_angle_to_pulse()`**：Q24 定点增益 + 64 位乘法四舍五入，
  180° 全程映射误差 < 0.5 µs（已用脚本穷举验证 0→180°，误差 0.44 µs、单调不回头）。
- **临界区**：所有改参数的操作都保存/恢复 `PRIMASK`，中断里读到的永远是完整一致的状态。
- **环形缓冲**：单生产者/单消费者无锁实现，接收 256 B、发送 512 B，
  `uart_puts()` 不会阻塞主循环（只有缓冲真满才等待，正常用不到）。
- **串口总线自适应**：`uart.c` 用 `#ifdef BOARD_UART_APB2EN` 区分 APB1/APB2，
  波特率按对应总线时钟算，所以从 USART1 换到 UART8 只需改 `config.h`。
