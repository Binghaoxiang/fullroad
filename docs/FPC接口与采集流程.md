# 主控板 16 个 FPC 是干什么的 + 单槽采集流程（以 FPC12 为例）

> 数据来源：主控板原理图网络表（`ProPrj_50寸主控026-09-21.epro` 逆向提取，176 脚逐脚核对）。

---

## 一、先给结论：每个 FPC 槽 = 一条"4 通道传感器 + 3 线 SPI"的总线口

16 个槽**引脚定义完全一样**，只有三样东西不同：**挂在哪条 SPI 上、用哪个片选、接哪 4 路模拟**。

| FPC 脚 | 信号 | 说明 |
|---|---|---|
| **1** | `+3P3V` | 给子板供电（3.3 V） |
| **2** | `SPIx_SCK` | 时钟（主机输出） |
| **3** | `SPIx_CSn` | **片选，每槽独立**（低有效） |
| **4** | `SPIx_MISO` | 数据（子板 → 主控） |
| 5 | 空 | 未连接 |
| **6~9** | **4 路模拟**（母线 01~20 中的 4 根） | 模拟信号进/出 |
| **10~12** | `GND` | 三根地，保证回流 |
| 13~15 | 未使用 | — |

**注意这一条**：槽里**没有 MOSI（主机→从机数据）**，也没有任何使能线。
所以这套槽是 **"只读 3 线 SPI + 模拟"** 的接口。

---

## 二、16 个槽的完整分配表

四组 SPI，每组最多 5 个槽；模拟母线 01~20 被各组复用。

| FPC | SPI 组 | 片选 | 模拟通道 | 备注 |
|---|---|---|---|---|
| **FPC16** | SPI4 | CS0 | 01 02 03 04 | |
| **FPC15** | SPI4 | CS1 | 05 06 07 08 | |
| **FPC14** | SPI4 | CS2 | 09 10 11 12 | |
| **FPC13** | SPI4 | CS3 | 13 14 15 16 | |
| **FPC12** | SPI4 | CS4 | 17 18 19 20 | ← 本文例子 |
| FPC11 | SPI5 | CS0 | 01 02 03 04 | |
| FPC10 | SPI5 | CS1 | 05 06 07 08 | |
| FPC9 | SPI5 | CS2 | 09 10 11 12 | |
| FPC8 | SPI5 | CS3 | 13 14 15 16 | |
| FPC7 | SPI5 | CS4 | 17 18 19 20 | |
| FPC6 | SPI6 | CS0 | 01 02 03 04 | SPI6 无 MOSI |
| FPC5 | SPI6 | CS1 | 05 06 07 08 | |
| FPC4 | SPI6 | CS2 | 09 10 11 12 | |
| FPC3 | SPI1 | CS2 | 09 10 11 12 | |
| FPC2 | SPI1 | CS1 | 05 06 07 08 | |
| FPC1 | SPI1 | CS0 | 01 02 03 04 | |

**规律**：每 5 个槽覆盖 20 路模拟（4 路/槽 × 5 槽 = 20），
四组 SPI 是四套并行的"同构总线"，可以同时接 4 组、也可以只接一组。

另外板上还有一个 **H5（20 脚排针）**，1~20 脚正好是 **01~20 这 20 路模拟母线** ——
它就是这套模拟总线的"总出口"，也正是 ADC64 板 **P3（20 脚：16 CH + REF + 3V3 + GND）**
的天然对接位置。

## 三、用 FPC12 举例：一脚一脚看

```
FPC12（15 脚 1.0mm，实际用 1~4、6~12）
┌────┬────────────┬──────────────────────────────────────┐
│ 脚 │ 网络名      │ 干什么用的                            │
├────┼────────────┼──────────────────────────────────────┤
│ 1  │ +3P3V      │ 给插在这里的子板供电（≤ 几十 mA）      │
│ 2  │ SPI4_SCK   │ 主控给子板的时钟（PE2 输出）           │
│ 3  │ SPI4_CS4   │ 只选这一个槽（低有效时才应答）         │
│ 4  │ SPI4_MISO  │ 子板把数据送回主控（PE5 输入）         │
│ 5  │ —          │ 空脚                                  │
│ 6  │ 17         │ 模拟母线第 17 路                      │
│ 7  │ 18         │ 第 18 路                              │
│ 8  │ 19         │ 第 19 路                              │
│ 9  │ 20         │ 第 20 路                              │
│10  │ GND        │ 地                                    │
│11  │ GND        │ 地                                    │
│12  │ GND        │ 地                                    │
└────┴────────────┴──────────────────────────────────────┘
```

**解读**：插在 FPC12 上的东西，能拿到 3.3 V 电源、一根时钟、一根自己的片选、一根回传数据线，
以及 4 根模拟线（17~20 号母线）。它**不能**从主控接收数据（没有 MOSI），
也**不会**收到任何使能信号。

## 四、采集是怎么进行的（时序层面）

主控只要做三步（固件里 `adc64.c` / `board.c` 就是干这个）：

```
1) CS  拉低           ← 选中 FPC12 上的这块子板
2) 打 16 个 SCK 脉冲  ← 每拍同时：主控在 MOSI 上发 1 bit（这里没接），子板在 MISO 上回 1 bit
3) CS  拉高           ← 一帧结束
```

主控收到的 16 bit 就是一次读数（ADS7953 的格式是：高 4 位=通道号回显，低 12 位=转换结果）。

**关键点**：这套接口是"主控只读"的。
- 如果子板是一块 **ADC**，它需要先被告诉"读哪个通道"（ADS7953 靠 SDI 送地址）——
  而 FPC 槽没有这根线，**所以原设计里 ADC 一定是通过别的路径拿到 SDI 的**（见第五节）。
- 如果子板是一个**自带扫描/移位输出的前端**，那它自己循环采集，主控只管按时钟收数据，
  三线就够 —— 这也是为什么这个槽只引出 SCK/CS/MISO 的最合理解释。

## 五、把 ADC64 板接到这套槽上的"缺口"

ADC64 板的数字侧 **P4（10 脚）** 需要 8 个信号：

```
NCS  SCLK  SDI  SDO  EN1  EN2  EN3  EN4     + 3.3V/GND
```

对比 FPC 槽能给的东西：

| ADC 板需要 | FPC 槽有吗 | 结论 |
|---|---|---|
| SCLK | ✅ 脚 2 | 直接接 |
| NCS | ✅ 脚 3 | 直接接 |
| SDO → 主控 MISO | ✅ 脚 4 | 直接接 |
| **SDI**（送通道地址） | ❌ 没有 | **必须飞线**到 PE6 / PC12 / PA7 |
| **EN1~EN4**（行选） | ❌ 没有 | **必须飞 4 根**到 PC0~PC3 |
| 3.3V / GND | ✅ 脚 1 / 10~12 | 直接接 |
| 模拟侧 CH0~CHF + REF | 经 **H5**（20 脚） | 用 H5 转接，或用 FPC 的 4 路模拟 |

> 所以"16 个 FPC 槽"这套接口，**和你手上的 ADC64 板不是完全配套的**：
> 槽能提供电源、SPI 三线、4 路模拟，但缺 SDI 和 4 路 EN。
> 这也解释了为什么我给的接线表里要额外飞 5 根线。

## 六、你现在这套（两条边）最省事的接法

**结论：不要试图把 ADC64 板"插"进 FPC 槽，直接飞线到 MCU 引脚最干净。**

| 用途 | 从哪里取 | 接到哪 |
|---|---|---|
| 3.3 V、GND | 主控板任意 3V3 / GND 焊盘（H6 全 3V3、H7 全 GND 最方便） | ADC 板 P4 |
| SCLK / NCS / SDO / SDI | MCU 引脚（飞线） | ADC 板 P4 |
| EN1~EN4 | MCU 的 PC0~PC3（飞线，两块板并联） | ADC 板 P4 |
| 模拟 CH0~CHF | 探测器板的列线 | ADC 板 P3（20 脚） |
| REF | ADC 板内部/外部基准 | P3 对应脚 |

具体引脚（与固件一致）：

```
板 A（长边）：SCLK=PE2  SDO=PE5  SDI=PE6  NCS=PE3
板 B（短边）：SCLK=PC10 SDO=PC11 SDI=PC12 NCS=PE4
共用：EN1~EN4 = PC0~PC3
```

**如果你更想复用 FPC 槽的 3 线 SPI**，那就把固件的 SPI 引脚改成槽对应的网络
（SCK=PE2、MISO=PE5 本来就是 SPI4 的引脚，和 FPC12~16 是同一组），
再单独飞 SDI + EN1~4 + 得到 CS 的 MCU 引脚即可 —— 前提是先确认 CS 网络到底连到 MCU 哪个脚
（我这边从原理图提取不到，需要你万用表量 FPC12 第 3 脚 ↔ MCU 引脚的连通性）。

---

## 七、一句话总结

- **16 个 FPC = 16 个"3 线 SPI + 4 路模拟 + 电源"的传感器插槽**，
  分 4 组 SPI，每组 5 槽、每槽一个独立片选；
- **数据是从子板"读"回来的**（SCK 打拍、MISO 收位），主控不需要发命令；
- **20 路模拟母线 01~20** 是这套系统的模拟主干，H5 是它的总出口；
- 你的 ADC64 板因为要 **SDI + EN**，只能"半借用"这套槽 —— 电源和三线 SPI 可用，
  另外 5 根必须飞线。
