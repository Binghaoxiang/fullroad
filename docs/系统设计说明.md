# 整套硬件设计思路说明（三块板为什么这么分工）

> 目标：让你理解**为什么**是这三块板、为什么是 64 路、为什么用二极管矩阵、
> 为什么 ADC 不放在主控板上。理解这些，后面接线和调参才不会踩坑。

---

## 0. 一句话：这是一套"64 通道光斑位置/倾角传感器"

```
激光斜射到光学膜 → 膜内出现十字光路 → 4 条边端面的探测器测光强分布
                                    → 64 路模拟量
                                    → 数字化 → STM32
                                    → 算"光斑偏哪边、偏多少"
                                    → 驱动舵机把光调正
```

它不是"读一个传感器"，而是**同时读几十个点的光强，用它反推光斑在膜上的位置和倾斜**。
所以整套硬件的核心矛盾是：**通道数多（64）但要连线少、模拟信号又要准**。

三块板就是为了解这个矛盾而拆开的。

---

## 1. 三块板的分工

```
┌─────────────────────────────────────────────────────────────┐
│  ① 探测器板  pin64-307-2835                                 │
│     64 只 PIN2835 光电二极管，4.8mm 间距排成 307mm 长条       │
│     + 64 只 SOD523 二极管（做行选开关）                       │
│     输出只有 20 根线：CH0~CHF（16 列）+ EN1~EN4（4 行）+ 电源   │
└───────────────────────────┬─────────────────────────────────┘
                            │ 20 根模拟/选通线（就近、短）
┌───────────────────────────▼─────────────────────────────────┐
│  ② ADC64 板                                                  │
│     ADS7953：16 通道 12bit 1MSPS SPI ADC                     │
│     74HC245：八路缓冲，保护/整形 SPI 线                       │
│     P3（20 脚）= 模拟输入侧                                   │
│     P4（10 脚 FPC）= 数字输出侧（SPI + EN + 电源）             │
│     → 一块板 = 16 个通道                                     │
└───────────────────────────┬─────────────────────────────────┘
                            │ 4 线 SPI（SCK/SDI/SDO/CS）+ EN
┌───────────────────────────▼─────────────────────────────────┐
│  ③ 50 寸主控板（STM32F429IGT6）                              │
│     16 个 FPC 槽 + 6 组 SPI + 20 脚模拟排针 H5                │
│     CH340C（USB 转串口）+ WiFi + 2 个 Type-C                  │
│     → 汇总数据、算结果、通过 USB/WiFi 传给上位机               │
└─────────────────────────────────────────────────────────────┘
```

**设计逻辑一句话**：
探测器板负责"把光变成 64 路电流"，ADC 板负责"把 16 路电流就地数字化"，
主控板负责"汇总 4 块 ADC 板的数据 + 对外通信 + 控制舵机"。

## 2. 为什么必须是 64 路、又必须拆成 4×16

### 2.1 为什么是 64 路

- 50 寸膜的边长约 1.2 m，要定位光斑/判断倾斜，**单点探测器完全不够**，
  必须在边上铺一条"线阵"看光强分布。
- 探测器间距 4.8 mm、一片条子长 307 mm 包 64 只，正好是"看得清光斑、又不太贵"的折中。

### 2.2 为什么不用 64 根线

64 根模拟线 + 地 + 屏蔽，走线、接插件、成本都不可接受。
于是用**矩阵复用（二极管矩阵）**：

```
        列线 CH0  CH1  CH2  …  CHF      ← 16 根读出线，接 ADC
       ┌──┬────┬────┬────┬───┬────┐
 R1 →  │D10│D11 │D12 │ …  │D1F │      ← EN1 有效时，这一行 16 只才导通
       ├──┼────┼────┼────┼───┼────┤
 R2 →  │D20│D21 │D22 │ …  │D2F │      ← EN2
       ├──┼────┼────┼────┼───┼────┤
 R3 →  │D30│D31 │D32 │ …  │D3F │      ← EN3
       ├──┼────┼────┼────┼───┼────┤
 R4 →  │D40│D41 │D42 │ …  │D4F │      ← EN4
       └──┴────┴────┴────┴───┴────┘
```

- **16 根列线 + 4 根行选 = 20 根**，正好是 ADC 板 P3 的 20 脚；
- 读法：EN1 有效 → 读 16 列 → EN2 有效 → 读 16 列 → … 4 次扫完 64 点；
- 每只光电二极管串联一个 SOD523 二极管（就是板上 64 个 `S**`），
  **行不选时二极管反偏截止，电流过不去**；行选中时才导通到列线。

### 2.3 这个设计的代价（后面调试会遇到的）

| 代价 | 现象 | 应对 |
|---|---|---|
| 串行扫描，速度 ÷4 | 64 点要扫 4 遍 | ADS7953 1 MSPS，全扫 < 1 ms，无所谓 |
| 二极管有正向压降 | 弱光时可能"读不到" | 光要足够强；本底要标定 |
| 行切换后要等稳定 | 切行瞬间读数跳变 | 固件里 `ADC64_EN_SETTLE_US`（默认 300 µs） |
| 矩阵有轻微串扰 | 相邻通道互相影响 | 归一化差分（S）能抵消大部分 |
| 被剪断的线会让整列/整行失效 | 某列恒 0 | 用掩码屏蔽（`K MASKA/B`） |

## 3. 为什么 ADC 不直接放主控板上

这是整套设计里最关键的一个决定：

**模拟信号（几十 µA 级的光电流）经 300 mm 以上的排线/软板传输，极易被干扰、
衰减、串扰。** 所以设计者把 ADC 板做小、**贴着探测器放**：

- 探测器 → ADC 板：模拟线只有十几厘米（20 脚排线）；
- ADC 板 → 主控板：走 **数字 SPI**，抗干扰能力强得多；
- 74HC245 的作用就是给这几十厘米的 SPI 线做缓冲、整形、防静电。

**代价**：多了一块板、多了 SPI 片选，还要在固件里做"多板轮询"。
**收益**：64 路模拟量能做得干净，这在微光检测里是决定性的。

这也解释了为什么主控板上有 **6 组 SPI、13 个片选**：
一组 SPI 总线可以挂多块 ADC 板，靠 CS 选通；通道多的系统就是"SPI 星型拓扑"。

## 4. 主控板上那些接口是干什么的

| 接口 | 用途 |
|---|---|
| **16 个 FPC 槽**（每槽 3V3/SCK/CS/MISO + 4 路模拟 + GND） | 接探测器/采集子板，一片槽服务一小段边 |
| **6 组 SPI**（SPI1/4/5 有 SCK/MISO/MOSI，SPI6 无 MOSI） | 多板并行采集，CS 区分 |
| **H5（20 脚，nets 01~20）** | 模拟通道汇总/测试点，正好对应 ADC 板的 P3 20 脚 |
| **CH340C + Type-C** | 插 USB 就是虚拟串口（UART8），给上位机传数据/收命令 |
| **另一个 Type-C（PA11/PA12）** | MCU 原生 USB（未用 CH340） |
| **WiFi（WIFI_IO/RESET/STA）** | 无线传数据（对应 UART2/UART4） |
| **16 路 FPC 的 4 路模拟** | 也可直接进主控做粗测/监视 |

> 注意：主控板的 SPI 只引出了 SCK/CS/MISO，**没有 MOSI，也没有 EN**。
> ADS7953 却需要 SDI 送通道地址、探测器板需要 EN 行选。
> 这说明原设计里这些线是走**另一条路**（H5 排针或另一个连接器），
> 也就是说：**主控板 + ADC64 + 探测器板 三者之间本来有一套专用线束**，
> 你现在用飞线替代，就必须把这 5 根（SDI + EN1~4）自己引出来。

## 5. 原来的系统设想 vs 你现在的两条边

### 原设计（推断）

```
      50 寸光学膜
   ┌─────────────────────────┐
   │        光学膜            │
   └─┬────┬────┬────┬────┬───┘
    条1  条2  条3  条4  …        ← 每条 307mm/64 只，铺满一条边
     │    │    │    │
   ADC1 ADC2 ADC3 ADC4           ← 4 块 16 通道 ADC 板 = 64 路
     └────┴────┴────┘
          SPI（CS 区分）
          │
      主控板 → USB/WiFi → PC → 软件算光斑位置 → 控制舵机
```

四周端面都铺的话就是 4 条边 × 64 = 256 路（示意图里只画了一条边）。

### 你现在做的（两条边、手工剪断）

```
      50 寸光学膜
   ┌─────────────────────────┐
   │                         │
   │   ●●●●●●●●●●●●●●●●● ← 长边：剪下来的那一段
   └─────────────────────────┘
                ●●●●●●●●●● ← 短边：另一段
```

- 每条边剩多少只、对应哪些 (行, 列)，是物理剪断的结果 → **必须实测标定**；
- 两条边各接一块 ADC 板（各 16 通道），
  - 长边 → 板 A → SPI4（PE2/PE5/PE6，CS=PE3）
  - 短边 → 板 B → SPI5（PC10/PC11/PC12，CS=PE4）
- EN1~EN4 两块板并联（同一行同时读两块），只要 4 根线；
- 固件里 `S = (长边总和 − 短边总和)/(两者之和)`，
  舵机把 S 调到 0 就是"光垂直入射"。

---

## 6. 为什么这样能判断"垂直"

这是设计里最巧妙的地方，也是你真正要理解的部分：

| 量 | 物理含义 | 数学性质 | 用来做什么 |
|---|---|---|---|
| **P = 两边总和** | 耦合进膜的总光量 | 关于垂直入射**偶对称**（垂直时最大） | 捕获光斑、粗调 |
| **S = (长 − 短)/(长 + 短)** | 光在两个方向上分配的不平衡 | 关于垂直入射**奇对称**（垂直时过零） | 精调、锁零 |

- 光越倾斜，光在膜内的传播方向越偏向某一侧，两条边的光强差越大 → **S 变大**；
- 正对入射时两边均等 → **S = 0**；
- 所以"把 S 调零"就等于"把光调垂直"，不需要知道绝对角度、也不受激光功率波动影响。

---

## 7. 总结：这套设计的三条主线

1. **空间上**：线阵探测器把"一个点"变成"一条线的光强分布" → 才能判断位置/倾角；
2. **电气上**：二极管矩阵把 64 根线压到 20 根；ADC 前移把模拟走线缩短到十几厘米；
3. **信息上**：用"总和"找光、用"差值"找垂直，两个信号分工，控制律就很稳。

理解了这三条，再看固件里的 `ADC64`（扫描矩阵）、`sensor`（算 S/P）、
`track`（状态机追 S=0）就一目了然了。
